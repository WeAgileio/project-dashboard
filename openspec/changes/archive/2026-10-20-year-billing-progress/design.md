## Context

見 `proposal.md`。請款任務的金額與完成狀態已在 `ProjectProgress` 的任務上。「請款進展·時間序」用截止日期字串的 `YYYY-MM` 把任務放進月欄，並在月欄表頭加總已收／總額。「請款進展」的 `projectBillingYearLines` 則用 `new Date(due).getFullYear()` 分年，只顯示已收／總額。「專案進展」的年份列只顯示年份。月份欄寬由月份列的請款字串決定，與年份列無關。

## Goals / Non-Goals

**Goals:**

- 三個頁面用同一套分年與百分比規則。
- 兩個時間序頁的年份合計只含目前畫面上的專案。
- 年份進度文字不改變月份欄寬。

**Non-Goals:**

- 不在「請款進展」加一條全專案的年份合計。
- 不改月份列的筆數、完成數或 💰 已收／總額。
- 不把請款任務改掛到階段所在的月份。

## Decisions

1. **共用純函式分年。** 新增一個不依賴 Vue 的函式：給一組請款任務，依截止日期字串的四碼年份加總已收與總額，並回傳四捨五入到整數的百分比；總額為 0 時百分比為空。兩個時間序頁與專案年份列都呼叫它。
   - 取代 `projectBillingYearLines` 裡的 `new Date(due).getFullYear()`。`YYYY-MM-DD` 若用 `Date` 解析，在負時區會掉到前一年，和月欄的字串解析不一致。
   - 考慮過在兩個 Vue 檔各寫一次迴圈。同一條請款會在三個頁面得到不同年份，所以不採用。

2. **時間序合計掃目前列出的專案。** 對該頁已套用搜尋與專案篩選後的項目，收集其中的請款任務再交給共用函式。年份表頭只在該年總額大於 0 時，於年份後顯示 `已收 / 總額  百分比`，千分位用 `zh-TW`。當地日曆的今年加上與「請款進展」今年列相同方向的高亮。
   - 考慮過把年份金額加進月份欄寬的測量字串。單月年份會把每一欄撐得很寬，所以年份文字不參與該測量；放不下時縮小進度文字，並用 `title` 放完整數字。

3. **「請款進展」只補百分比。** `projectBillingYearLines` 改走共用函式，年份列在既有已收／總額後加上百分比。今年高亮與沒有金額就不列出該年的行為維持不變。不新增頁首合計。

## Risks / Trade-offs

- [「專案進展」的年份金額不等於該年欄位裡看得到的階段] → 接受。金額跟請款任務自己的截止日期，規格已寫明。
- [只跨一個月的年份格放不下整段金額] → 不撐開月欄；縮小進度文字，完整數字放在 `title`。
- [既有專案年份列改用字串年份後，負時區下的分年會和現在不同] → 這是要和月欄對齊的修正。台北時間（UTC+8）下 `YYYY-MM-DD` 的 `Date` 解析本來就不會跨年。

## Migration Plan

只改前端顯示。不需資料遷移。還原時拿掉年份後的進度文字，並讓專案年份列回到只顯示已收／總額即可。
